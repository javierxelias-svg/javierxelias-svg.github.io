01 · The shape

Six thousand listings in, five out.

Aggregators repost the same job with a fresh URL and a rounded-off salary. So the system skips them and reads employers directly — Ashby, Greenhouse and Lever expose their own posting APIs, which return the real range and the real location rules. Cheap filters run first, expensive ones last, and it remembers everything it has already shown me so nothing repeats.

02 · The interesting part

Three times it was confidently wrong.

Every one of these was found the same way — by opening the source instead of trusting my own output. None of them were visible in the data the system had.

CASE 01A salary that was 3× the real one

A role surfaced at $237,375. The number looked wrong for the level, so I opened the posting. It was OTE — on-target earnings, base plus commission. The guaranteed base was $75,541–$92,428. Nothing in the feed said so; the figure was simply presented as pay.

system said$237,375 actually guaranteed$75,541 fixevery figure is now base; OTE is labelled OTE
CASE 02Two pay tiers blended into one headline

An employer's own API returns two compensation tiers — one for expensive metros, one for everyone else. Their public board displays a single blended range. A remote candidate outside those metros reads a number they will not be offered. The gap between what the system stores and what the user sees is not a bug in either; it is the seam where support tickets are born.

CASE 03Ranked third. Broke both of my hard rules.

A role came back third out of sixty-three at $187,500, marked fully remote and all base. I opened it. Hybrid, three days a week in an office, and paid on commission. Two root causes, and neither was in the module I first blamed: the parser read one "is this remote" field and ignored a contradicting one sitting beside it, and the pay string it was handed had silently dropped the words "On Target Earnings" before it ever arrived. The salary parser was correct the whole time. It was fed a lossy string.

system saidremote · $187,500 base · rank 3 posting said3 days in office · OTE learnedcheck what the function received before rewriting what it does

A correct parser fed a lossy string looks exactly like a broken parser. That one cost me two hours and it is the most useful thing I learned all month.

03 · The rule underneath

It is not allowed to tell me something worked.

The workspace this runs inside forbids the sentence "this should work." Nothing counts as done because it looks done — only when it has run and left a receipt on disk. Every number on this page has a file behind it: the run log, the test output, the raw API response. That constraint is the reason I caught all three of the above instead of shipping a digest that quietly lied to me every morning.

It is also why the system has eighteen test files and why each of the three fixes above is pinned by a regression test, so it cannot come back. Honesty enforced by the machine, not by willpower.
